# 01 · Architecture

Two halves joined by files. A batch pipeline (Python, `services/seismic`) writes an immutable run directory; an exporter turns one chosen run into a static data bundle; the web app (`apps/web`) reads only that bundle through a provider. Nothing on the demo path depends on a live service.

## Pipeline

```
EarthScope FDSN ──► inventory ─► download ─► pick ─────────► associate ─► locate ─► match ─► tier ─► magnitude
 (station,           H1          H1          H1  (PhaseNet)   H2          H2        H2       H2      H2 (P1)
  dataselect)                                 └► baseline ──┐                                          │
                                                H1 (STA/LTA) │                                          ▼
Public catalog ──► catalog (H2) ────────────────────────────┼──────────────► match          validate (H4) ─► export (H4)
 (event service)                                            └──► validate (H4): same associator + locator    │
                                                                                                           ▼
                                                             apps/web/public/data/<mode>/ ──► providers ──► web app
                                                             services/api (Live, P1) ────────► LiveProvider
```

Every stage is a function `run(ctx: RunContext) -> None` that reads and writes files in the run directory (`docs/02` → Stage API). `hq run configs/showcase` runs them in order; `hq stage <name> --run <runId>` reruns one.

| Stage | Owner | Module | Reads | Writes (in `data/showcase/runs/<runId>/`) |
| --- | --- | --- | --- | --- |
| inventory | H1 | `hq.ingest.inventory` | config | `stations.parquet` (+ StationXML in `data/cache/stationxml/`) |
| catalog | H2 | `hq.match.catalog` | config | `catalog.parquet`, `catalog.quakeml` |
| download | H1 | `hq.ingest.download` | `stations.parquet` | `gaps.parquet` (+ mseed in `data/cache/mseed/`) |
| pick | H1 | `hq.pick.run` | cache, stations | `picks.parquet`, `known/` (known-event windows, record sections) |
| baseline | H1 | `hq.baseline.run` | cache, stations | `picks_stalta.parquet`, `baseline_sweep.parquet` |
| associate | H2 | `hq.associate.run` | picks, stations | `assoc_events.parquet`, `assoc_picks.parquet` |
| locate | H2 | `hq.locate.run` | assoc, picks, stations, grids | `events_located.parquet`, `residuals.parquet`, `statics.parquet`, `synthetic.json` |
| match | H2 | `hq.match.run` | located events, catalog | `matches.parquet`, `match_sensitivity.parquet` |
| tier | H2 | `hq.tier.run` | located events, matches | `events.parquet` (final `SeismicEvent` rows), `sweep.parquet` (association sweep rerun through locate, match and tier) |
| magnitude | H2 | `hq.magnitude.run` | events, cache | updates `events.parquet`, `magnitude.json` |
| validate | H4 | `hq.validate` | everything above | `validation.json` |
| export | H4 | `hq.export` | everything above + cache | `apps/web/public/data/<mode>/` |

Rules that make reruns cheap:

- **Pick once, store everything.** Picks are stored at probability ≥ 0.1; association and location filter from there. Changing an association threshold never re-picks.
- **Waveforms download once** into `data/cache/mseed/` and are shared by every run.
- **Every run records its full config** in `run.json` (`ProcessingRun`), so every number on screen traces to a config.

## Conventions

Everything uses one vertical: **`elevM`, meters above sea level, up positive.** That covers stations, sensors, hypocenters and wells. Depth exists only as a derived display field.

| Quantity | Canonical form | Notes |
| --- | --- | --- |
| Time | `t`: epoch seconds UTC, float64 | Microsecond-safe. UI shows UTC plus Utah local (MDT, UTC−6 in September). |
| Showcase window | Explicit UTC start and end in `configs/showcase/run.yaml` | Catalog query and waveform window use the same bounds. A different day boundary changes the public count, so it's always re-queried, never assumed. |
| Horizontal | UTM zone 12N (EPSG:32612) meters minus the origin | GDR FORGE catalogs ship in UTM 12, so comparisons are free |
| Origin | One fixed reference point (lat, lon, elevM) in `run.yaml` | Chosen once at 8:05 PM, never recomputed |
| ENU | `e`, `n` = UTM offset from origin; `u` = `elevM − originElevM` | meters |
| Sensor elevation | `sensorElevM = surfaceElevM − sensorDepthM` | `sensorDepthM` comes from the StationXML **channel** `depth` field. Borehole sensors sit far below their wellhead. |
| Display depth | `depthKm = (refSurfaceElevM − elevM) / 1000` | UI label: "Depth below site surface (ref N m ASL)". Always visible next to the depth ruler. |
| Catalog depth | Converted into `elevM` using its stated datum | Record the datum in `CatalogEvent.depthDatum` |
| Scene axes (three.js) | x = east, y = up, z = −north; 1 scene unit = 1 km | Right-handed, y-up |
| Vertical exaggeration | Default 1.0 | Any other value shows a permanent "Vertical ×N" badge |
| Magnitude | Value plus `magType`, always | Never compare across types |
| Names | Unit suffixes in field names: `M`, `S`, `Km`, `Hz`, `Deg` | `rmsS`, `hErrM`, `sampleRateHz` |

## Data bundle (what the web app reads)

```
apps/web/public/data/<mode>/        mode = mock | showcase | snapshot
  meta.json              BundleMeta: schemaVersion, mode, SceneMeta, ProcessingRun, AnalysisSummary
  stations.json          Station[]
  catalog.json           CatalogEvent[] (matchedEventId filled in)
  events.json            SeismicEvent[] (~400 B each; < 1 MB at 2,000 events)
  features.json          GeoFeature[] (wells/facilities, each with a SourceRef)
  validation.json        Validation
  evidence/{eventId}.json   EventEvidence (20–60 KB each)
                            place each trace by its own t0 (x = t0 + i·dt − event.t); windows need not share an origin

apps/web/public/terrain/            region-wide, same for every mode (H3)
  height.png  hillshade.png  meta.json
```

## Moving data between laptops

Code travels through git. Data doesn't: each laptop has its own `data/`, and none of it is committed.

| What | How it moves | Size |
| --- | --- | --- |
| Run tables (`data/showcase/runs/<runId>/`) | `make publish-run RUN=<id>` uploads a tarball as a GitHub prerelease `run-<id>`; `make fetch-run RUN=<id>` downloads and unpacks it; `make runs` lists them | MBs |
| Waveform cache (`data/cache/mseed`, `stationxml`) | H1 downloads it once. Around 10:30 PM H1 hands the whole `data/cache/` folder to H4 by AirDrop or USB. Nobody else needs it. | GBs |
| Travel-time grids, velocity files (`data/cache/ttgrids`, `velocity`) | Regenerated by H2's code wherever it's needed | varies |
| Web bundle (`apps/web/public/data/showcase/`) | Committed to git by H4's exporter and merged through `main` | < 30 MB |

One run flows through the lanes under a single `runId`: H1 runs inventory → pick and publishes; H2 fetches, runs associate → tier and republishes; H4 fetches, runs validate → export. **H4's laptop is the pipeline of record:** at the pipeline freeze, H4 reruns every stage end to end from merged `main` and the shared cache, so the final numbers come from one reproducible run.
