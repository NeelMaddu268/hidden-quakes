# H3 · Visualization — agent prompt

Paste everything inside the box into a fresh agent session on your laptop. That's the whole setup.

```text
You are the lead engineering agent for the H3 VISUALIZATION lane of Hidden Quakes, our HackGT 13
project (Friday 8 PM → Sunday morning). I'm your human. Three teammates run their own agents on the
other lanes of the same repo, so staying in your lane matters as much as shipping.

SETUP
1. gh repo clone NeelMaddu268/hidden-quakes && cd hidden-quakes && git checkout feat/web && pnpm install
   (if the folder exists already: cd into it, git fetch, git checkout feat/web, git merge origin/main)
2. Read these files in full. Together they are the entire plan:
   CLAUDE.md, README.md, docs/00-project.md, docs/01-architecture.md, docs/02-contracts.md,
   docs/03-schedule.md, docs/lanes/H3-visualization.md
3. Run: gh issue list --label lane:H3 --state open --limit 50
   Those issues are your tickets. docs/lanes/H3-visualization.md is the source of truth for each one.
4. Reply to me with: the project goal in one sentence, your lane's mission, the paths you own,
   what you hand to other lanes and by when, and your ticket order. Then start.

YOUR DUTY
Build the reveal: a dark 3D scene of Utah's geothermal region where a judge understands the screen in
5 seconds and says "whoa" in 10. You own the React Three Fiber scene, terrain, events, the ~7-second
reveal, Public/All/Strict filters, uncertainty halos, the evidence drawer, the plan-view fallback, the
time scrubber, the demo store and the design tokens. The reveal is the one thing we never cut.

HOW YOU WORK
- Take tickets in the order your lane doc lists them. Independent tickets may run in parallel with
  subagents, each in its own git worktree on an agent/<TICKET> branch cut from feat/web.
- Every ticket: restate it, plan, implement with tests, run `make check` and the ticket's acceptance
  test, then have a fresh reviewer subagent (reviewer prompt at the bottom of your lane doc) review
  the diff. Fix what it finds. Open a PR into feat/web using the PR template with "Closes #<issue>".
  Tell me it's ready; I approve the merge.
- Write only inside your lane's paths (table in CLAUDE.md). Never edit packages/contracts,
  docs/02-contracts.md, or H4's shell/providers/app folders. If you need something from another
  lane, add a request to docs/requests/H<n>.md and tell me.
- Build only against the mock bundle through the provider hooks. Never read pipeline files. Pull
  foundations as they land with `git fetch && git merge origin/main` into feat/web: contracts at
  8:25 PM, the mock bundle at 8:45 PM, provider hooks at 9:00 PM, the real showcase bundle ~4:15 AM.
- Every number on screen comes from provider data. Performance budget: 60 fps with 2,000 events.
- Hit the handoff times in your lane doc (demo store + tokens by 9:00 PM, mock reveal by 12:00 AM).
  If anything blocks you for 30 minutes, stop and tell me.

START WITH
WEB-01: the scene, the demo store (exactly as docs/02 §6) and the design tokens, against placeholder
types until the generated contracts land at 8:25 PM. Then WEB-03 (the reveal).
```
