### REQ-H2-3 · hq_contracts.io: dtype-stable to_frame
- From: H2 (lead agent, message to H4)
- Needed by: before any lane writes an empty or all-null table
- What: `to_frame` built frames with `DataFrame.from_records` and no dtypes, so a zero-row frame or an all-`None` column came out `object` in pandas and Arrow `null` in parquet, and `t` was not guaranteed `float64`. Now every flattened column's dtype comes from the model field annotation (`io.dtypes_for`): `float` → `float64` (NaN for None); `int` → `int64`, or nullable `Int64` when the field is optional or sits inside an optional nested model; `bool` → `bool` / `boolean` likewise; `str`, `Literal[...]`, str enums and `dict` (JSON text) → `string`; `list`/`tuple`/anything else → `object`. `write_table` therefore writes the real Arrow types (`double`, `int64`, `bool`, `string`) for empty and all-null columns, `read_table` restores the same pandas dtypes, and `from_frame` maps `pd.NA`, NaN and `None` to `None` and hands `string`/`Int64`/`boolean` cells to pydantic as plain `str`/`int`/`bool`. Also the optional ask: the shared `Model` base now sets `allow_inf_nan=False`, so a NaN/inf float is a validation error (a missing value is `None`). No schema change, `SCHEMA_VERSION` and `columns_for` order unchanged.
- Why it blocks: column types differed from run to run (`magnitude_*` with no magnitudes, `catalogMatch_*` with no matches, H1's pick `eventId`/`residualS`/`weight`), and empty tables wrote Arrow `null` columns.
- Status: done (agent/CONTRACT-02)
