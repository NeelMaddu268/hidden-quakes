### FYI-H2-1 · Public-catalog depths and scene north (for H3 and H4)
- From: H2 (agent on MATCH-01)
- What:
  - UU depths in ComCat are below sea level (UUSS catalog datum; source recorded in `CatalogEvent.depthDatum`). Display depth for public events must come from `CatalogEvent.elevM`: `depthKm = (refSurfaceElevM - elevM) / 1000`. The published `depthKm` is relative to sea level, not the site surface.
  - ENU follows the UTM 12N grid (docs/01), so scene north is grid north, which differs from true north by the grid convergence at the origin (about a degree).
- Status: FYI

### FYI-H1-1 · Station.surfaceElevM and Station.id details (for H2, H3 and H4)
- From: H1 (agent on SEIS-01)
- What:
  - `sensorDepthM` is always the StationXML channel depth, and `sensorElevM = surfaceElevM - sensorDepthM` always holds.
  - `surfaceElevM` is the ground surface at the sensor's site, checked against the USGS 3DEP DEM at the sensor position. It is not always the raw StationXML station elevation. For some borehole stations, StationXML's station elevation is already the sensor level; there `surfaceElevM` is the station elevation plus the channel depth. For a shallow sensor whose StationXML elevation misses the DEM by more than `stations.elevation.maxShallowMismatchM`, `surfaceElevM` is the DEM value (`onShallowMismatch: dem`). The raw value and the decision for every station are in `inventory_report.json`.
  - The docs/02 comment on `surfaceElevM` ("StationXML station elevation (wellhead for boreholes)") describes the common case. If H4 wants the comment to say "site ground surface (DEM-checked)", that is a docs/02 PR; no field changes.
  - When two locations of one site are both kept, `Station.id` is `NET.STA.LOC` with the raw location code. An empty location code therefore gives `NET.STA.`, which is the exact id SEIS-05 builds for its cache lookups.
- Status: FYI
