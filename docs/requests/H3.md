### REQ-H2-1 · Public-event depth comes from elevM, never CatalogEvent.depthKm
- From: H2 (reviewer on MATCH-01)
- Needed by: before public events render with a depth readout
- What: `CatalogEvent.depthKm` is the published depth, which for this catalog is km below sea level (see `depthDatum`). `SeismicEvent.depthKm` is km below `refSurfaceElevM`. Same field name, different datums. Place public events from `enu`/`elevM`, and compute any depth shown next to our events as `(refSurfaceElevM - elevM) / 1000` under the "Depth below site surface" label. If the published value is shown at all, label it "published depth, km below sea level".
- Also: ENU follows the UTM 12N grid (docs/01), so scene north is grid north. That differs from true north by the grid convergence at the origin (about a degree). Don't rotate data to true north, or everything stops lining up with the terrain and stations.
- Status: open

### REQ-H4-1 · FYI: what the mock bundle (FIX-01) exercises, and what it does not
- From: H4 (agent on FIX-01)
- Needed by: none (FYI; nothing to build)
- What: facts about `apps/web/public/data/mock/` that the scene, drawer and scrubber should rely on, so switching to `?mode=showcase` is a mode change and not a rewrite:
  - The hero id comes from `meta.scene.heroEventId`; never hard-code an event id (the ids change whenever the generator's seed or geometry changes).
  - `revealOrder` is a full permutation `0..N-1`, Tier A → B → C, time-ordered within each tier; never re-sort in the browser.
  - Evidence traces are placed by their own `t0` (`x = t0 + i·dt − event.t`); windows do not share an origin (each opens 1 s before that trace's predicted P).
  - Nullable fields that the mock actually leaves null on some records: `pickS`/`probS` (stations beyond `nS`), `predP`/`predS` (a few far traces, blanked together), `quality.hErrM` (Tier C only), `quality.vErrM`, `magnitude`, `magnitude.sigma`, `catalogMatch`, `CatalogEvent.mag`/`magType`. `pickP`/`probP` are always set.
  - Station `kind` is only `surface` or `borehole` in the mock (no `strong_motion`). 17 stations, 16 used: one surface station has `usedInRun: false` and appears in no pick, trace or `run.stationIds`.
  - Boreholes carry `staticsS` with a `P` entry only (no `S`); surface stations may carry both or none.
  - Station, well, facility and boundary elevations follow a smooth synthetic relief (a bowl rising toward the station ring), not the real DEM under `apps/web/public/terrain/`; expect them to float above or below the baked terrain in mock mode only.
  - Evidence files span 4 traces (the Tier C event with the fewest stations) to 16 traces (the hero); every file is under 60 KB.
- Why it blocks: nothing. It avoids assumptions in the scene/drawer that the showcase bundle would also break.
- Status: FYI

### REQ-H4-2 · Point the scene at `@/providers` and delete `scene/bundle-shim.ts`
- From: H4 (reviewer on DEMO-01)
- Needed by: 12:00 AM Sat (Gate M: mock reveal in the deployed build with shell and providers)
- What: `apps/web/src/scene/data.ts` still re-exports `useBundle` from the temporary `scene/bundle-shim.ts`, whose own "delete when H4's hooks land" condition was met when API-01 reached `main`. The shim fetches `/data/<mode>/` a second time next to the provider, carries its own `SCHEMA_VERSION` literal, and bypasses `mockAllowed()`. In a production build with `?mode=mock` the shell shows "Data unavailable" (mock disabled) while the scene still renders the mock bundle without the SYNTHETIC banner. Replace the re-export with `export { useBundle } from "@/providers";` (same `BundleState` shape, docs/02 §6), delete the shim and its `types.ts` duplicate if any, and drop the second fetch. `useMode()` is also exported from `@/providers` if the scene needs the mode label.
- Why it blocks: the Definition of done says mock, showcase and snapshot load through the same components with zero code changes; two readers of the same bundle can disagree on version, mode gating and errors.
- Status: open
